# Physical cockpit and exterior glass visibility

2026-10-19, production/homepage-rebuild. Supersedes detached-dashboard rendering
and the prior `ship.visible = t < 1` behavior.

## Correction

The website explicitly hid the entire spaceship after boarding and displayed a
separate dashboard-only render. That caused the loss of cockpit context.
The GLB canopy existed, but its original combination of very low opacity and
full transmission made it nearly invisible in this web lighting.

The full ship now remains visible in one Three.js scene and one renderer. Removed
the second dashboard canvas/renderer and cloned dashboard scene. Live display text,
heart Home target, and physical destination hit areas project from the original
ship's world-space geometry into the full-viewport HTML control overlay.
The original hull, collar, tub and control deck remain around the pilot view.

Pilot eye is (0,.29,-.12) × source root scale 1.04, looking toward
(0,.24,.12) × 1.04. Interior FOV 110 degrees in portrait / 65 in landscape;
vertical view offset .22 portrait / .04 landscape preserves the forward view
while keeping the original controls inside the viewport. These are web camera
settings, not edits to Blender cameras or geometry.

Exterior canopy has a cloned runtime material with opacity .36, transmission 0,
roughness .085, IOR 1.45, clearcoat 1, thickness .006 and env intensity 1.5.
This transparent reflective approximation makes the dome visible; it is not final
physically accurate refractive glass. Home closes and restores it; boarding
lifts/slides it, and it stays out of view after entry. The rest of the ship stays.
Reflection environment is now generated by the single main renderer, shared by
all ship/scenery materials. No new dependency, model export or Blender launch.
